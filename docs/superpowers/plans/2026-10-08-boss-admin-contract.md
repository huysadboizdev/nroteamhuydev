# Boss Admin Live implementation contract

Approved plan: `2026-10-08-boss-admin-live-draft.md`, user approved implementation in chat.

Catalog artifacts: `SRC/data/boss_admin_catalog.json` mirrored `admin/includes/boss_admin_catalog.json` on web. Array of entries `{key,boss_id,class_name,name,quest,limited,kind,phases:[{phase,name,hp,damage,maps}],drop_summary}`. key `id:<semantic BossID>` for standard bosses, `class:<full Java class>` for dynamic mini/training missing stable IDs. No constructor calls to enumerate.

Table `boss_admin_config`: boss_key VARCHAR(160), phase INT, hp INT NULL, damage INT NULL, cap_damage INT NULL, cap_percent DECIMAL(7,3) NULL, apply_mode VARCHAR(16) default 'next', drop_mode VARCHAR(16) default 'default', drops LONGTEXT default '[]', revision BIGINT; primary(boss_key,phase). cap_percent limits actual player HP damage as percent of hpMax, distinct default skill damage. Table `boss_admin_state`: id=1,revision BIGINT; `boss_admin_audit`: id auto, boss_key,phase,revision,actor_id,before_json,after_json,created_at. Old boss_live_override retained fallback for standard ID if no new config.

RELOAD_BOSS payload stays `{catalog_patch: {boss_admin:true,revision:N}}` with existing command ACK queue. SQL changes and command queued transaction atomically; optimistic per-row expected revision. Global revision increments per save/reset/rollback. stage snapshot reads state+config validates all, publish revision monotonic. apply_mode='alive' boss tick applies hp ratio/damage once per life+revision; next is spawn only. Outgoing cap from hit next. Unchanged default behaviors keep old calculation. Java service `BossAdminConfig`: `keyFor(Boss)`, `config(Boss)` nullable, `stage(Connection)` Runnable, `applyAtSpawn(Boss)`, `applyAtTick(Boss)`, `limitDamage(Player attacker, Player target,long damage)`; config record accessors hp(),damage(),capDamage(),capPercent(),applyMode(),dropMode(),drops(),revision(). Java drop type record Rule(String group,int itemId,int quantityMin,int quantityMax,int chanceBp,int weight,List<Item.ItemOption> options); chanceBp=0..10000, units0.01%; groups empty independent, nonempty mutually exclusive group shares chanceBp and weighted members.

Drop service `BossAdminDropService.reward(Boss,Player,Runnable defaultReward)` executes default sideeffects once and applies configured drops without exposing suppressed ItemMap to zone. Boss.reward final wrapper; subclasses rename reward override to rewardDefault and super.reward to super.rewardDefault. ItemMap/Service drop publication hook owned by drop task. Reset life hook owned by runtime task calls drop.reset(Boss) (coordinate before editing Boss.java). Drop policy captured immutable once per death, preserve quest rewards and kill credit, avoid duplicate deaths.

Ownership: runtime task owns BossAdminConfig/BossLiveReload/LiveSyncCatalogCommands/Player damage hook/Boss tick+spawn; drops task owns BossAdminDropService/ItemMap/Service drop hook/subclassreward refactor.
